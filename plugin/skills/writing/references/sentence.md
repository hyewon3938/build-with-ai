# writing §1 문장 구조 세부 규칙

SKILL.md §1 규칙마다 실제 지적 사례와 교정 예시, 지적 경위, 예외를 전부 모았고, 절 번호는 SKILL.md와 같다.

## 1. 문장 구조 — 금지 패턴 (전부 실제 지적 사례)

### 1-1. 짧은 단정 꼬리문장 · 여운 마무리
"~가 아니다." 식으로 짧게 끊어 강조하거나, 짧은 문장으로 멋지게 마무리하는 영어식 punch line.
- ✕ 외로움은 답을 못 들어서 생기는 게 아니다. 잘 대답해주는 상대가 있다고 채워지지 않는다.
- ✕ 그런 순간이 오면 된다. / 이 경험은 만들어진 것이다. / 지금도 매일 돌아갑니다.
- ○ 앞 문장에 이어 붙이거나 보통 길이의 서술로 끝낸다: "현재까지 매일 사용 중인 시스템입니다."

### 1-2. 짝대기(—)·콜론 뒤 임팩트 문장, 편집자적 부제
- ✕ 기준은 하나다 — 유저가 이 존재의 메시지를 기다리게 되는가.
- ✕ '정직한 검증 한계' '(발굴 아닌 검증)' 같은 부제·괄호 라벨 장식.
- ○ 쉼표로 잇거나 문장으로 푼다. 부제는 달지 않는다.

### 1-3. 선나열-후회수 화법 (대표적 번역투)
앞에 요소를 줄줄 나열해 놓고 마지막에 한 번에 받는 구조.
- ✕ 답장이 빨라지고 느려지는 것도, 먼저 건네는 말도 모두 그 삶에서 나옵니다.
- ○ 캐릭터는 자기 삶을 기반으로 답장 텀과 대화 소재가 정해집니다.

### 1-4. 재료 문장 이어붙이기
이력서 불릿·JD 문장·이전 버전 문서를 그대로 이어 붙이면 바로 티가 난다 ("줄줄이 이어붙인 느낌").
- 문장마다 판단(왜·그래서)이 담기고, 앞 문장을 받아 이어져야 한다. 조사 하나로도 잇는다:
  "고도화하는 과정을 반복해왔습니다" → "고도화하는 과정도 반복해왔습니다".
- JD 문구는 같은 자리에 같은 단어를 쓰되(검색 매칭), 문장 자체를 복사하지 않는다.

### 1-5. 부정 후 긍정 ("~가 아니라 ~다")
- ✕ 한 번에 큰 감정을 주는 게 아니라, 일상에 스며들 때 애착이 생긴다.
- ○ 한 번에 큰 감정을 주는 것보다는 일상에 계속 함께할 때 애착이 생긴다. (부정 대신 비교로 순화)

### 1-6. 어중간한 종결
- 명사형·나열형으로 끝내지 않는다: "케이스로." → "케이스로 처리." / "유지가 어려워짐" → "유지가 어려워져 체계로 관리".
- 이유 설명("~하기 때문이다")보다 결과 통보("~하도록 구성했습니다", "~에 넣었습니다")가 기본형.
- **시스템을 주어로 한 순수 현재형 종결만 이어지면 번역투로 읽힌다.** "관리가 복잡해지지 않습니다", "새벽에 정리해 업데이트합니다"처럼 결과를 현재형으로만 서술하지 말고, 만든 사람이 드러나는 종결("~하지 않도록 구성했습니다", "~하도록 해뒀습니다")을 주된 표현으로 쓴다.

### 1-7. 문장형 타이틀 · 압축 조어 라벨
타이틀과 불릿 라벨은 짧은 명사구로, 읽기 전에 내용이 예측돼야 한다.
- ✕ 문장형: '먼저 말을 걸고, 답이 없으면 연락을 멈춘다'
- ✕ 압축 조어(단어를 그냥 붙임): '시간 3층 구조' '답장행동' '선톡 5종' '상시 가동'
- ○ '기억 저장 항목 3가지' + 친절한 설명. 압축이 안 되면 설명으로 전부 잇는다. 풀어 쓸 때 층·계층으로 부르지 않고 몇 가지인지 센다(§2-8).
- 어필성 타이틀 금지: '1인 풀스택' 같은 자기 홍보 라벨 ✕ → '인프라 구성' 같은 실무 명칭.
- **타이틀·라벨·범례·표 머리글은 `~다`로 끝내지 않는다** (2026-08-25 설계 허브 지적). 문장 종결형을 짧은 라벨에 쓰면 미완성 문장처럼 읽힌다. 명사나 명사형으로 끝낸다.
  - ✕ 코드가 적는다 → ○ 코드가 자동 기록 / ✕ 모델이 만든다 → ○ 하루 한 번 모델이 생성
  - ✕ 오늘 계획을 만든다 → ○ 오늘 계획 생성 / ✕ 계획대로 보낸 시간은 적지 않는다 → ○ 계획대로 보낸 시간은 기록 없음
  - **수동태 라벨도 금지.** ✕ 대화 중에 적힌다 → ○ 대화를 통해 업데이트 (행위자를 숨긴 채 당하는 꼴로 쓰지 않는다)
  - 적용 범위는 카드 제목, 부제, 박스 제목, 박스 아래 한 줄 설명, 범례, 표 머리글, 각주 한 줄. 툴팁·본문처럼 여러 문장이 이어지는 산문은 평서형 그대로 둔다.
- **의문형 타이틀 금지** (2026-08-26 설계 허브 지적, 같은 지적이 여러 차례 반복돼 명시). 제목 자리에 질문을 쓰면 번역투로 읽히고, 답을 읽기 전까지 무슨 내용인지 알 수 없다. 질문의 답을 명사구로 바꿔 단다.
  - ✕ 왜 값으로 바꾸나 → ○ 값으로 바꾸는 이유 / ✕ 왜 두 단어인가 → ○ 두 단어 조합의 키
  - ✕ 어떻게 고르나 → ○ 고르는 방법 / ✕ 몇 줄까지 넣나 → ○ 프롬프트에 넣는 순서와 개수
  - ✕ 어느 항목 것인가 → ○ 저장 항목 사이의 순서 / ✕ 언제 것인가 → ○ 같은 항목 안의 순서
- **조건절로 끝나는 라벨도 문장형이다.** `~하면`, `~오면`처럼 뒷말이 잘린 꼴로 끝내지 않고 `~할 때`, `~한 연락`처럼 명사로 닫는다.
  - ✕ 유저가 붙잡으면 → ○ 유저가 붙잡을 때 / ✕ 자는 시간에 연락이 오면 → ○ 자는 시간에 온 연락
  - ✕ 각본이 늦으면 → ○ 각본이 늦어질 때 / ✕ 유저가 오래 답이 없으면 → ○ 유저가 오래 답이 없을 때
- **`~것`으로 끝내도 설명 문장을 줄인 꼴이면 문장형 타이틀이다** (2026-09-13 노션 기능 문서 지적). 동사가 들어간 설명을 명사절로 접어 제목에 올리면 번역투로 읽힌다. 제목만 보고 무엇을 다루는지 알 수 있게 다루는 대상의 이름으로 단다.
  - ✕ 반응을 보고 배우는 것 → ○ 플러팅 반응 점수 / ✕ 단계가 오르면 늘어나는 연락 → ○ 단계별 하루 연락 상한
  - ✕ 플러팅이 나오는 자리 → ○ 플러팅하는 상황

### 1-8. 괄호 보충 설명
- ✕ (이벤트와 컨디션이 인과로 엮여 있다)
- ○ 문장에 녹인다: "각 이벤트는 서로 인과 관계를 형성하며, 회식이 있던 다음 날엔 피곤해하는 식으로 나타납니다."

### 1-9. 결론 먼저 짧게 던지고 뒤에서 설명하기 (영어 문단 구조)

한 문장으로 결론을 툭 세우고 다음 문장에서 근거를 붙이는 topic sentence + supporting sentence 구조. 한국어로 옮기면 바로 번역투·AI 말투로 읽힌다. **이유와 결론을 한 문장에 묶는다.**
- ✕ 그 자리를 지금 챗봇이 채우기엔 부족했습니다. 유저가 먼저 말을 꺼내야 하고, 며칠 만에 말을 걸면 지난 이야기를 오늘 처음 하듯 받습니다.
- ○ 지금 챗봇은 유저가 먼저 말을 꺼내야 하고 며칠 만에 말을 걸면 지난 이야기를 오늘 처음 하듯 받아서, 그 자리를 채우기엔 부족합니다.
- ✕ 답장 텀도 일정마다 지정하지 않고 두 태그 조합으로만 정했습니다. 일정이 늘수록 하나하나 관리하기 어려워지기 때문입니다.
- ○ 답장 텀은 일정마다 지정하면 종류가 늘수록 관리하기 어려워져서, 두 태그의 조합으로만 정했습니다.
- §1-1(짧은 단정 꼬리문장)과 한 쌍이다. 1-1은 문단 끝, 1-9는 문단 앞. **짧은 문장이 혼자 서 있으면 앞뒤 어느 쪽이든 의심한다.**
- 예외: 문단 첫 도입 한 문장(예: `텔레그램으로 대화합니다.`)도 뒤 문장과 이을 수 있으면 잇는다. 끊어야만 하는 이유가 없으면 잇는 쪽이 기본.

### 1-10. 감정·상태 명사를 주어 자리에 앉히기

사람이 하는 일을 마음·느낌·감각 같은 추상 명사가 대신 주어가 되는 번역투. **사람을 주어로 되돌린다.**
- ✕ 연결이 그리운 마음은 남습니다. / 사람과 이어져 있다는 느낌은 남아 있습니다.
- ○ 사람과 이어지는 건 여전히 그리워합니다.
- ✕ 흥미가 초반에 붙들리지 않을 수 있습니다. → ○ 초반에 흥미를 붙들지 못할 수 있습니다.
- ✕ 내일 다시 찾을 이유는 남지 않는다. → ○ 다시 찾아올 이유가 없어 도구로만 쓰다 만다. (이유·마음·느낌이 `남다/사라지다`의 주어가 되어 문장을 끝내지 않는다 — 주어는 사람·유저)
- §2-1(의인화)과 다르다. 2-1은 사물이 살아 움직이는 것, 1-10은 감정·상태가 주어 자리를 차지하는 것.

### 1-11. 정의 문장에 예시를 끼워 붙이고 부연으로 마무리하기 (2026-09-13 노션 기능 문서 지적)

개념을 설명하는 문장이 `~보다 ~를 뜻해서, ~도 ~합니다`처럼 비교로 정의하다가 곧바로 예시 행동을 이어 붙이고, 다음 문장에서 반대쪽 예시로 한 번 더 설명하는 구조. 설명하다 말고 갑자기 예를 드는 것처럼 읽히고, 정의보다 `~인 건 아니다`라는 해명이 앞에 선다. **정의는 정의만 담아 쓰고, 예시가 필요하면 표나 뒤 문단의 제자리에 둔다.**
- ✕ 관계 단계는 좋아하는 마음의 크기보다 그 마음을 얼마나 드러내고 얼마나 요구하는지의 수위를 뜻해서, 1단계 캐릭터도 유저가 흘린 말을 기억해 뒀다가 다음에 먼저 묻고 또 이야기할 이유를 남깁니다. 별명을 부르거나 보고 싶었다고 말하는 건 사이가 그만큼 가까워진 다음입니다.
- ○ 캐릭터는 처음부터 유저에게 이성적인 호감을 갖고 있습니다. 관계 단계는 그 호감을 얼마나 표현하고 유저에게 얼마나 요구하는지에 따라 4단계로 나눴습니다.
- 마지막 문장이 앞 내용을 다른 말로 한 번 더 설명하면 지운다. §3의 구구절절 금지와 같은 뿌리다.

### 1-12. 부정을 앞세워 긍정을 강조하기 (2026-09-13 노션 기능 문서 지적)

`~하지 않아서 ~합니다`, `~하지 않고 ~합니다`처럼 하지 않는 일을 문장 앞에 세우고 정작 하는 일을 뒤에 붙이는 구조. 읽는 사람 눈에는 앞에 나온 부정이 먼저 들어와 그대로 기억에 남는데, 문장이 전하려는 내용은 뒤의 긍정이라 핵심이 뒤로 밀린다. §1-5의 `~가 아니라 ~다`와 같은 부류이고, `아니라` 같은 대조 표지 없이 연결 어미로만 이어져서 쓰는 사람이 알아채기 더 어렵다. **하는 일을 먼저 쓰고, 하지 않는 일은 꼭 필요할 때만 뒤에 덧붙인다.**
- ✕ 3단계에서 4단계로 넘어가는 마음 확인은 기간이 지나도 저절로 채워지지 않아서, 고백하는 때와 고백한 뒤의 행동을 따로 적었습니다.
- ○ 3단계에서 4단계로는 기간과 상관없이 마음 확인 한 번으로 넘어가서, 캐릭터가 언제 고백하는지와 고백한 뒤 어떻게 행동하는지를 따로 적었습니다.
- ✕ 캐릭터는 날짜를 기준으로 고백하지 않고, 그동안의 대화를 보고 판단할 때 고백합니다. → ○ 캐릭터는 그동안의 대화를 보고 유저도 마음이 있다고 판단할 때 고백합니다.
- ✕ 당분간 다시 고백하지 않고, 하던 플러팅을 더 적극적으로 합니다. → ○ 하던 플러팅을 더 적극적으로 하고, 다시 고백하는 것은 당분간 미룹니다.
- ✕ 조건을 다 채운 날에도 바로 넘어가지는 않고, 새벽 정리에서 한 번 더 판단합니다. → ○ 조건을 다 채우면 새벽 정리에서 한 번 더 판단합니다.
- 하지 않는 일 자체가 전하려는 내용인 문장(고백에 답을 재촉하지 않습니다)과 조건절(유저가 받아 주지 않으면)은 대상이 아니다.
