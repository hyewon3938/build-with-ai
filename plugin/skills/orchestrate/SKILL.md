# /orchestrate — 멀티에이전트 실행 플레이북

## 입력

$ARGUMENTS

사용자가 이 스킬을 호출한 것 자체가 **멀티에이전트 오케스트레이션에 대한 명시적 opt-in**이다 — 다수의 서브에이전트를 쓰고, Workflow 도구가 있는 환경이면 Workflow도 쓴다. 토큰을 아끼느라 커버리지를 줄이지 않는다.

## 역할 선언

너는 이 작업의 **지휘자(orchestrator)**다. 직접 노동(대량 파일 읽기, 반복 수정)을 하지 않는다. 지휘자의 일은 분해, 지시서 작성, 품질 판정, 종합이다.

## 절차

### 1. 정찰 — 작업 공간 파악

- 인라인 빠른 스캔(구조·대상 목록) 또는 scout 1-2개로 작업 목록을 만든다.
- 팬아웃 계획(몇 개를 어떤 단위로, 검증은 어떻게)을 2-3문장으로 사용자에게 알리고 바로 진행한다.

### 2. 분해 — 독립 단위로

- 서로 의존성 없는 단위로 쪼갠다. 같은 파일을 만지는 단위 둘을 동시에 실행하지 않는다.
- 단위마다 지시서 4요소를 갖춘다: ① 목적+배경(에이전트는 이 대화를 못 본다 — 자립적으로) ② 정확한 범위 ③ 반환 형식 ④ 금지 사항.

### 3. 병렬 실행

- 독립 단위는 **한 메시지에 여러 Task 호출**로 동시에 띄운다.
- 역할별 에이전트: 탐색 = scout, 구현 = worker, 검증 = verifier. 기계적 스캔은 haiku/sonnet급, 판단이 필요한 일은 메인과 동급 모델.
- 팬아웃이 5개 이상이고 다단계 파이프라인이면, Workflow 도구가 있는 환경에서는 Workflow 스크립트로 처리한다 (pipeline() 우선, 배리어는 전 단계 결과가 전부 동시에 필요할 때만).

### 4. 적대적 검증

- 중요한 발견·변경마다 verifier를 병렬로 붙여 반박을 시도시킨다. 여러 개 붙일 땐 관점을 다르게 (정확성 / 재현 여부 / 부작용).
- REFUTED는 버리고, UNCERTAIN은 그 라벨 그대로 보고에 포함한다. 검증을 통과한 것만 "확인됨"으로 말한다.

### 5. 종합

- 최종 보고는 지휘자가 직접 작성한다. 서브에이전트 출력 이어붙이기 금지.
- 구조: 결과 요약(첫 문장) → 확인된 것들(근거 포함) → 탈락·불확실 → 커버리지 한계(못 본 영역).

## 규모 가이드

- 빠른 확인: scout 1-2개, 검증 생략 가능
- 일반 작업: 에이전트 3-6개 + 핵심 결론 1-2건 검증
- "전부", "철저히", "감사" 요청: finder 풀 확대 + 발견 전수 검증 + 새 발견이 2라운드 연속 0건일 때까지 반복 (loop-until-dry)
