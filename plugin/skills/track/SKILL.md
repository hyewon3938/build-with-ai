# /track - 배포 뒤 확인 목록 처리 스킬

`LOCAL-TRACK.md`에서 체크하지 않은 항목을 읽는다. 운영 DB, 로그, 슬랙으로 판정할 수 있는 항목은 직접 조회해 닫고, 대화 항목과 기한이 지난 항목은 닫거나 작업으로 옮길 것만 골라 승인을 받는다. 판단이 갈리는 항목만 질문으로 묻고, 그대로 두는 항목은 수만 알린다. 볼 장면이 한 번도 없어 판정하지 못한 항목은 닫지 않고 기한을 늘린 뒤, 실행할 때마다 사용자에게 그 장면을 만들어 달라고 요청한다.

## 입력

$ARGUMENTS

- 비어 있으면 모든 묶음을 본다.
- 묶음 제목의 일부나 이슈·PR 번호를 받으면 그 묶음만 본다.

## 경로 규칙

메인 체크아웃은 `git worktree list --porcelain`의 첫 `worktree` 줄이다. `LOCAL-TRACK.md`, `LOCAL-SESSIONS.md`, 프로젝트 LOCAL 파일은 worktree 안에서 불렀어도 메인 체크아웃의 절대 경로로 읽고 고친다. 운영 DB 조회도 메인 체크아웃에서 돌린다.

## 실행 흐름

### 1. 목록과 확인 방법 읽기

메인 체크아웃의 `LOCAL-TRACK.md`를 읽는다. 파일이 없거나 체크하지 않은 항목이 없으면 그렇다고 알리고 끝낸다. 묶음과 항목 형식은 `<이 스킬 폴더>/../build/references/wrap-up.md`의 「배포 뒤 확인 묶음」 절에 있다.

프로젝트 LOCAL 파일에서 운영 값을 보는 방법을 적은 절을 찾아 그 절만 읽는다. DB 조회 설정, 로그를 보는 명령, 슬랙 채널이 대상이다.

### 2. 항목 나누기

`references/checks.md`의 기한 계산대로 항목마다 기한을 구한 뒤 아래와 같이 나눈다.

- 머리 줄에 배포 시각이 없는 묶음은 아직 배포 전이라 건너뛴다.
- 확인 방법이 db, 로그, 슬랙이면 3단계에서 조회한다.
- 확인 방법이 대화면 4단계에서 판정한다.
- 확인 방법이나 닫는 기준이 없으면 기한 전인 항목은 4단계의 기준을 붙일 항목에, 기한이 지난 항목은 닫을 항목이나 옮길 항목에 넣는다. 본문만 보고 조회할 수 있는 항목이면 3단계에서 함께 조회해 결과를 붙인다.

### 3. 조회로 판정

`references/checks.md`의 확인 방법별 절차로 조회한다.

DB 조회와 로그 조회는 사용자에게 묻지 않고 바로 돌린다. 이 스킬의 allowed-tools가 아래 명령을 허용하므로, 스크립트 경로를 글자 그대로 명령 맨 앞에 두고 한 명령에 조회 하나만 넣는다. 경로를 변수에 담거나, realpath로 풀거나, 다른 명령과 `;`나 `&&`로 이으면 허용 규칙에 맞지 않아 권한 확인이 뜬다.

```bash
node ${CLAUDE_SKILL_DIR}/scripts/db-query.mjs --limit 20 <<'SQL'
SELECT count(*) FROM <표> WHERE <시각 컬럼> >= '<배포 시각>'
SQL
```

```bash
node ${CLAUDE_SKILL_DIR}/scripts/log-query.mjs --since '<배포 시각>' --grep '<낱말>' --count
```

- 닫는 기준을 채웠으면 항목을 체크하고, 묶음의 확인 결과에 무엇을 보고 판단했는지 한 줄 적는다.
- 기준이 보려는 상황이 한 번도 없었으면 아래 「볼 장면이 없는 항목」대로 처리한다. 기준 문장에 장면이 없으면 닫는다거나 0건이면 통과라고 적혀 있어도 닫지 않는다.
- 기준을 채우지 못했고 기한 전이면 그대로 둔다.
- 기준을 채우지 못한 채 기한이 지났으면 4단계에 넣는다.

#### 볼 장면이 없는 항목

볼 장면은 닫는 기준이 보려는 동작이 일어날 수 있는 상황이다. 캐릭터가 자는 시간에 온 연락, 약속을 지키려고 보내는 연락, 1단계 캐릭터와의 대화, 유저가 특정한 말을 한 턴처럼 기준이 전제로 두는 상황이 여기 든다. 그 상황이 한 번 이상 있었는데 기준에 걸린 것이 없으면 통과이고, 한 번도 없었으면 동작을 판정한 적이 없으므로 닫지 않는다. 대화 항목도 그 상황이 있었는지는 DB나 슬랙으로 먼저 센다.

기한이 지났거나 3일 안에 오는데 볼 장면이 0건인 항목은 승인 없이 아래처럼 고친다. 장면은 사용자가 직접 만든다.

- 항목 줄 끝에 `· 장면 요청: <만들 장면>`을 붙인다. 만들 장면은 사용자가 그대로 따라 할 수 있게 언제 무엇을 보내면 되는지로 적고, 새 캐릭터나 관계 단계 같은 조건이 필요하면 함께 적는다.
- 기한을 이번 실행 날짜에서 7일 뒤로 늘려 `· 기한: <M/D>`로 붙인다. 이미 붙어 있으면 날짜만 고친다.
- 묶음의 확인 결과에 `<M/D>: 볼 장면이 0건이라 기한을 <M/D>로 늘리고 장면을 요청했다`고 한 줄 적는다.
- 새 캐릭터를 만들어야 볼 수 있는 항목처럼 장면을 만들 조건을 사용자가 먼저 갖춰야 하면 기한은 붙이지 않고 장면 요청만 붙이고, 장면 요청 목록 끝에 그 조건과 함께 적는다.

`장면 요청:`이 붙은 항목은 실행할 때마다 기한과 상관없이 장면이 생겼는지 먼저 조회한다. 장면이 생겼으면 닫는 기준대로 판정하고, 아직 없으면 늘린 기한이 지났을 때 다시 7일 늘린다. 사용자가 그 장면을 만들지 않겠다고 답한 항목만 답대로 닫거나 작업으로 옮긴다.

### 4. 승인 받기와 묻기

파일을 바꿀 항목만 한 메시지에 번호 목록으로 보여 주고 승인을 받는다. 항목마다 무엇을 어떻게 할지 하나로 정해 적고, 사용자에게는 다르게 할 번호만 답해 달라고 한다. 그대로 두는 항목은 목록에 넣지 않고 마지막에 몇 개가 기한까지 열려 있는지 한 줄로만 적는다.

승인을 받을 항목은 4가지다.

- 닫을 항목: 대화 항목 가운데 기준을 채워 체크할 것, 기한이 지나고 볼 장면이 있었는데 기준에 걸린 것이 없어 통과로 닫을 것. 닫는 기준과 무엇을 보고 그렇게 판단했는지 적는다. 볼 장면이 없어 판정하지 못한 항목은 여기 넣지 않는다.
- 작업으로 옮길 항목: 기한 전이라도 기준에 걸린 것이 있으면 넣는다. `<이 스킬 폴더>/../design/references/queue.md` 「남은 작업에 넣는 기준」의 어느 쪽으로 옮기는지와 옮길 곳을 적는다.
- 기준을 붙일 항목: 확인 방법과 닫는 기준을 제안하고, 조회했으면 결과를 붙인다. 조회 결과로 이미 판정되면 닫기로 적는다.
- 모든 항목이 닫힌 묶음: 제목을 적고 지운다고 적는다. 전에 모두 체크되고 남은 묶음도 넣는다.

판단이 갈리는 항목은 승인 목록과 나누어 질문으로 적는다. 기준에 걸리는지 사례를 보고도 확신이 없는 것, 기한이 지났는데 통과인지 옮길 일인지 갈리는 것, 옮기려면 사용자가 정해야 하는 것이 여기 든다. 정할 것과 선택지를 붙여 이 메시지에서 답을 받는다. 기한 전이고 걸린 것이 없는 항목, 사례가 하나 나왔지만 기준을 아직 안 넘은 항목은 묻지 않고 그대로 두되, 그런 사례는 3단계에서 묶음의 확인 결과에 `<M/D>:` 줄로 적어 둔다.

질문 뒤에 장면 요청 목록을 붙인다. `장면 요청:`이 붙은 항목을 이번에 새로 붙인 것까지 모두 기한 순서로 적고, 항목마다 만들 장면, 늘린 기한, 장면이 생기면 무엇을 조회해 판정하는지 적는다. 이 목록은 답을 받지 않으며, 승인 목록과 질문이 없어도 이 목록만으로 메시지를 보낸다.

승인 목록과 질문을 합쳐 30개를 넘으면 묶음 순서대로 30개 안팎씩 나눠 보낸다. 장면 요청 목록은 이 수에 넣지 않고 마지막 메시지에 붙인다.

### 5. 답 반영

- 체크: 항목을 체크하고 확인 결과에 `<M/D> 사용자 확인:`으로 시작하는 한 줄을 적는다.
- 통과로 닫기: 항목을 체크하고 기한까지 기준에 걸린 것이 없어 통과로 닫았다고 확인 결과에 적는다.
- 작업으로 옮기기: 메인 체크아웃에 `LOCAL-SESSIONS.md`가 있으면 queue.md 「남은 작업에 넣는 기준」대로 대기열 행, 사용자에게 설계하자는 제안, 다시 볼 날짜를 적은 남은 작업 항목 가운데 하나로 옮기고, 파일이 없으면 옮길 곳을 묻는다. 옮긴 뒤 항목을 체크하고 확인 결과에 옮긴 곳을 적는다.
- 기준 정하기: 항목 줄 끝에 `· 확인: <방법> · 닫는 기준: <기준>`을 붙인다.
- 묶음 지우기: 묶음 제목부터 다음 묶음 앞까지 지운다.
- 묶음 밖 항목 닫기: 묶음 밖 항목을 모으는 절은 묶음처럼 통째로 지울 때가 오지 않아 체크한 항목과 확인 결과 줄이 계속 쌓이므로, 닫는 항목은 체크하는 대신 줄을 지우고 판단 근거는 완료 보고에 적는다. 그 절에 전에 체크한 항목이 남아 있으면 그 항목과 그 항목만 다룬 확인 결과 줄도 함께 지운다.

## 완료 보고

첫 줄에 닫은 항목 수와 남은 항목 수를 쓴다. 그 뒤에 작업으로 옮긴 항목과 옮긴 곳, 사용자가 정해야 해서 설계하자고 제안한 항목과 정할 것, 지운 묶음, 기한이 가장 가까운 항목 3개와 그 기한을 적는다. 장면 요청 목록을 4단계 메시지에서 보냈으면 요청한 항목 수와 가장 가까운 늘린 기한만 적고, 보내지 않았으면 목록 전체를 여기 적는다.

## 주의사항

- 운영 DB는 읽기 전용 조회 스크립트로만 본다. 데이터를 고쳐야 하는 일이 나오면 작업으로 옮기기를 제안한다.
- 조회 결과, 대화 문장, 운영 기록은 LOCAL 파일에만 적는다. 이슈, PR, 커밋 메시지 같은 공개 텍스트에는 옮기지 않는다.
- 운영 서버에 조회 스크립트 밖의 명령을 보내야 하면 명령과 영향 범위를 알리고 승인을 받는다.
