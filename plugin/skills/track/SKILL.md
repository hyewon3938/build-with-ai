# /track - 배포 뒤 확인 목록 처리 스킬

`LOCAL-TRACK.md`에서 체크하지 않은 항목을 읽는다. 운영 DB, 로그, 슬랙으로 판정할 수 있는 항목은 직접 조회해 닫고, 대화를 봐야 판정할 수 있는 항목과 기한이 지난 항목, 닫는 기준이 없는 항목은 모아서 한 번에 묻는다.

## 입력

$ARGUMENTS

- 비어 있으면 모든 묶음을 본다.
- 묶음 제목의 일부나 이슈·PR 번호를 받으면 그 묶음만 본다.

## 경로 규칙

메인 체크아웃은 `git worktree list --porcelain`의 첫 `worktree` 줄이다. `LOCAL-TRACK.md`, `LOCAL-SESSIONS.md`, 프로젝트 LOCAL 파일은 worktree 안에서 불렀어도 메인 체크아웃의 절대 경로로 읽고 고친다. 운영 DB 조회도 메인 체크아웃에서 돌린다.

## 실행 흐름

### 1. 목록과 확인 방법 읽기

메인 체크아웃의 `LOCAL-TRACK.md`를 읽는다. 파일이 없거나 체크하지 않은 항목이 없으면 그렇다고 알리고 끝낸다. 묶음과 항목 형식은 `<이 스킬 폴더>/../build/references/wrap-up.md`의 「배포 뒤 확인 묶음」 절에 있다.

프로젝트 LOCAL 파일에서 운영 값을 보는 방법을 적은 절을 찾아 그 절만 읽는다. DB 조회 설정, 로그를 보는 명령, 슬랙 채널이 대상이다.

### 2. 항목 나누기

`references/checks.md`의 기한 계산대로 항목마다 기한을 구한 뒤 아래와 같이 나눈다.

- 머리 줄에 배포 시각이 없는 묶음은 아직 배포 전이라 건너뛴다.
- 확인 방법이 db, 로그, 슬랙이면 3단계에서 조회한다.
- 확인 방법이 대화면 4단계 질문에 넣는다.
- 확인 방법이나 닫는 기준이 없으면 기한 전인 항목은 기준을 제안하는 질문에, 기한이 지난 항목은 기한 지난 항목 질문에 넣는다. 본문만 보고 조회할 수 있는 항목이면 3단계에서 함께 조회해 질문에 결과를 붙인다.

### 3. 조회로 판정

`references/checks.md`의 확인 방법별 절차로 조회한다.

- 닫는 기준을 채웠으면 항목을 체크하고, 묶음의 확인 결과에 무엇을 보고 판단했는지 한 줄 적는다.
- 기준을 채우지 못했고 기한 전이면 그대로 둔다.
- 기준을 채우지 못한 채 기한이 지났으면 4단계 질문에 넣는다.

### 4. 모아서 묻기

아래 4가지를 한 메시지에 번호 목록으로 보여 주고 항목마다 제안을 하나씩 붙인다. 사용자에게는 제안과 다르게 할 번호만 답해 달라고 한다.

- 대화 항목: 닫는 기준과 볼 장면을 적는다. 제안은 체크 또는 그대로 두기다.
- 기한이 지난 항목: 기한과 지금까지 확인한 것을 적는다. 제안은 통과로 닫기 또는 작업으로 옮기기다. 작업으로 옮기기를 제안할 때는 `<이 스킬 폴더>/../design/references/queue.md` 「남은 작업에 넣는 기준」의 어느 쪽인지 함께 적고, 사용자가 정해야 하는 일이면 정할 것과 선택지를 붙여 이 질문에서 답을 받는다.
- 기준이 없는 항목: 확인 방법과 닫는 기준을 제안하고, 조회했으면 결과를 붙인다. 조회 결과로 이미 판정되면 닫기를 제안한다.
- 모든 항목이 닫힌 묶음: 제목을 적는다. 제안은 지우기다.

항목이 30개를 넘으면 묶음 순서대로 30개 안팎씩 나눠 묻는다.

### 5. 답 반영

- 체크: 항목을 체크하고 확인 결과에 `<M/D> 사용자 확인:`으로 시작하는 한 줄을 적는다.
- 통과로 닫기: 항목을 체크하고 기한까지 기준에 걸린 것이 없어 통과로 닫았다고 확인 결과에 적는다.
- 작업으로 옮기기: 메인 체크아웃에 `LOCAL-SESSIONS.md`가 있으면 queue.md 「남은 작업에 넣는 기준」대로 대기열 행, 사용자에게 설계하자는 제안, 다시 볼 날짜를 적은 남은 작업 항목 가운데 하나로 옮기고, 파일이 없으면 옮길 곳을 묻는다. 옮긴 뒤 항목을 체크하고 확인 결과에 옮긴 곳을 적는다.
- 기준 정하기: 항목 줄 끝에 `· 확인: <방법> · 닫는 기준: <기준>`을 붙인다.
- 묶음 지우기: 묶음 제목부터 다음 묶음 앞까지 지운다.

## 완료 보고

첫 줄에 닫은 항목 수와 남은 항목 수를 쓴다. 그 뒤에 작업으로 옮긴 항목과 옮긴 곳, 사용자가 정해야 해서 설계하자고 제안한 항목과 정할 것, 지운 묶음, 기한이 가장 가까운 항목 3개와 그 기한을 적는다.

## 주의사항

- 운영 DB는 읽기 전용 조회 스크립트로만 본다. 데이터를 고쳐야 하는 일이 나오면 작업으로 옮기기를 제안한다.
- 조회 결과, 대화 문장, 운영 기록은 LOCAL 파일에만 적는다. 이슈, PR, 커밋 메시지 같은 공개 텍스트에는 옮기지 않는다.
- 운영 서버에 조회 스크립트 밖의 명령을 보내야 하면 명령과 영향 범위를 알리고 승인을 받는다.
