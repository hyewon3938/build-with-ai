# 기한 계산과 확인 방법별 절차

## 기한 계산

기한은 묶음 머리 줄의 배포 시각에 닫는 기준의 기간을 더한 때다.

- 머리 줄 형식은 `<M/D> 머지 · <M/D HH:MM> 배포 · 이슈 #N · PR #M`이고, 배포 시각은 `/deploy`가 넣는다. 형식이 다른 옛 머리 줄은 배포라는 말 앞뒤에 적힌 날짜와 시각을 읽고, 시각이 없으면 그날 0시로 계산한다.
- 닫는 기준에 `배포 뒤 3일 안에`처럼 기간이 있으면 그 기간을 더한다.
- 기준에 횟수만 있거나 닫는 기준이 없으면 배포 뒤 7일을 기한으로 삼는다.
- 항목 본문에 확인할 날짜를 따로 적었으면 그 날짜를 기한으로 삼는다.

## db

조회 스크립트는 `<이 스킬 폴더>/../../scripts/db-query.mjs`다. 프로젝트 권한 설정은 이 스크립트를 절대 경로 문자열로 허용하므로, `realpath`로 심링크와 `..`를 푼 경로를 먼저 얻고 그 경로로 부른다. 메인 체크아웃에서 돌리고 SQL은 heredoc으로 넘긴다.

```bash
node <스크립트 절대 경로> --limit 20 <<'SQL'
SELECT count(*) FROM <표> WHERE created_at >= '<배포 시각>'
SQL
```

- 접속 정보는 메인 체크아웃 `.env`의 `DB_QUERY_SSH_HOST`, `DB_QUERY_CONTAINER`, `DB_QUERY_PATH`다. 설정 오류로 끝나면 `<이 스킬 폴더>/../../scripts/env-has.mjs`로 세 이름이 있는지만 보고, 빠진 이름을 사용자에게 알린다. 값은 사용자가 넣는다.
- SELECT나 WITH로 시작하는 한 문장만 돌아간다. 결과는 기본 50행, 한 칸 300자에서 잘리고 행 줄을 합쳐 20만 자를 넘으면 뒤 행이 빠지므로, `count`나 `max`로 먼저 좁힌 뒤 필요한 행만 읽는다.
- 출력은 잘려도 서버는 값 전체를 만든다. `group_concat`으로 여러 행을 한 값으로 합치거나 큰 BLOB을 `hex`로 바꾸는 조회는 그 크기만큼 운영 서버 메모리를 쓰므로, 길이가 필요하면 `length`로 읽는다.
- 표와 컬럼 이름은 프로젝트의 스키마 문서나 `pragma_table_info('<표>')` 조회로 확인한다.
- 종료 코드 1은 조회 실패, 2는 사용법이나 설정 오류다. 오류 문장을 그대로 보고하고 같은 조회를 되풀이하지 않는다.
- 저장 시각의 시간대가 배포 시각과 다를 수 있다. 프로젝트 문서에서 시각을 어느 시간대로 저장하는지 확인하고 비교한다.

## 로그

프로젝트 LOCAL 파일에 적힌 명령으로 배포 때 저장한 로그 파일이나 지금 컨테이너 로그를 보고, 기준에 적힌 낱말을 찾는다. 원격 명령은 자동 승인에서 막힐 수 있으니 명령을 보여 주고 승인을 받는다. 컨테이너를 다시 만들면 로그가 사라지므로, 다음 배포 전에 로그로만 볼 수 있는 항목은 기한이 남아 있어도 이번에 본다.

## 슬랙

Slack MCP의 읽기 도구인 `slack_search_public_and_private`, `slack_read_channel`, `slack_read_thread`로 프로젝트 LOCAL 파일에 적힌 채널을 본다. 배포 시각 뒤의 게시만 보고, 판정에 쓴 글은 게시 날짜와 시각을 확인 결과에 적는다. 메시지를 보내거나 리액션을 다는 도구는 쓰지 않는다.

## 대화

대화 항목은 사용자에게 묻는다. 볼 장면을 사용자가 찾기 쉽도록, DB나 슬랙에서 해당 턴의 시각을 찾을 수 있으면 질문에 함께 적는다.
