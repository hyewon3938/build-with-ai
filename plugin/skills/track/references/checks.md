# 기한 계산과 확인 방법별 절차

## 기한 계산

기한은 묶음 머리 줄의 배포 시각에 닫는 기준의 기간을 더한 때다.

- 머리 줄 형식은 `<M/D> 머지 · <M/D HH:MM> 배포 · 이슈 #N · PR #M`이고, 배포 시각은 `/deploy`가 넣는다. 형식이 다른 옛 머리 줄은 배포라는 말 앞뒤에 적힌 날짜와 시각을 읽고, 시각이 없으면 그날 0시로 계산한다.
- 닫는 기준에 `배포 뒤 3일 안에`처럼 기간이 있으면 그 기간을 더한다.
- 기준에 횟수만 있거나 닫는 기준이 없으면 배포 뒤 7일을 기한으로 삼는다.
- 항목 본문에 확인할 날짜를 따로 적었으면 그 날짜를 기한으로 삼는다.
- 항목 줄에 `· 기한: <M/D>`가 붙어 있으면 그날 23:59를 기한으로 삼고 위 계산보다 앞세운다. 볼 장면이 없어 기한을 늘린 항목이 이 형식을 쓴다.

## db

조회 스크립트는 `<이 스킬 폴더>/scripts/db-query.mjs`이고, 플러그인의 `scripts/db-query.mjs`를 가리키는 심링크다. 스킬 프런트매터의 allowed-tools가 스킬 폴더 경로를 그대로 붙인 이 명령을 허용하므로 조회마다 사용자에게 묻지 않는다. SKILL.md 3단계의 명령 예시에 치환된 경로를 글자 그대로 쓰고, `realpath`로 풀거나 변수에 담지 않는다. 메인 체크아웃에서 돌리고 SQL은 heredoc으로 넘긴다.

allowed-tools는 스킬을 부른 턴에만 적용된다. 승인 목록에 답을 받은 뒤의 턴에서 조회하면 권한 확인이 뜰 수 있으니, 그 턴에서도 묻지 않고 돌리려면 프로젝트 권한 설정에 같은 명령을 허용해 둔다.

- 접속 정보는 메인 체크아웃 `.env`의 `DB_QUERY_SSH_HOST`, `DB_QUERY_CONTAINER`, `DB_QUERY_PATH`다. 설정 오류로 끝나면 `<이 스킬 폴더>/../../scripts/env-has.mjs`로 세 이름이 있는지만 보고, 빠진 이름을 사용자에게 알린다. 값은 사용자가 넣는다.
- 조회 스크립트는 사용자가 고정한 프로젝트 폴더와 조회 대상에서만 돈다. 사용자가 메인 체크아웃에서 터미널을 열고 `node <이 스킬 폴더>/../../scripts/query-pin.mjs`를 직접 돌려, 화면에 나온 대상과 접속 주소를 확인하고 고정한다. 조회는 ssh 설정 파일을 읽지 않고 고정할 때 풀어 둔 접속 값으로만 접속하고, 경유 호스트를 쓰는 호스트는 고정하지 않는다. 고정한 뒤 `.env`의 조회 설정이 바뀌면 조회가 고정 오류로 멈추고, ssh 설정을 바꾼 것은 사용자가 다시 고정해야 조회에 반영된다. 고정 오류로 멈추면 오류 문장에 나온 명령을 사용자에게 전하고 기다린다. 고정 파일을 직접 쓰거나, 가짜 터미널로 query-pin을 돌리거나, 다른 폴더에서 돌리는 식으로 우회하지 않는다. 조회 명령 앞에 환경 변수를 붙이지 않고, ssh 설정 파일과 고정 파일, 조회 스크립트는 고치지 않는다. worktree에서 부르면 메인 체크아웃에서 부르라는 문장으로 멈추는데, 이때는 고정을 요청하지 않고 그 경로에서 다시 부른다.
- SELECT나 WITH로 시작하는 한 문장만 돌아간다. 결과는 기본 50행, 한 칸 300자에서 잘리고 행 줄을 합쳐 20만 자를 넘으면 뒤 행이 빠지므로, `count`나 `max`로 먼저 좁힌 뒤 필요한 행만 읽는다.
- 출력은 잘려도 서버는 값 전체를 만든다. `group_concat`으로 여러 행을 한 값으로 합치거나 큰 BLOB을 `hex`로 바꾸는 조회는 그 크기만큼 운영 서버 메모리를 쓰므로, 길이가 필요하면 `length`로 읽는다.
- 표와 컬럼 이름은 프로젝트의 스키마 문서나 `pragma_table_info('<표>')` 조회로 확인한다.
- 종료 코드 1은 조회 실패, 2는 사용법이나 설정 오류다. 오류 문장을 그대로 보고하고 같은 조회를 되풀이하지 않는다. ssh 연결 실패로 끝났으면 분류된 오류를 보고하고 멈춘다. 다시 고정하라고 먼저 권하지 않고, 사용자가 ssh 설정을 직접 바꿨다고 말할 때만 다시 고정을 안내한다.
- 저장 시각의 시간대가 배포 시각과 다를 수 있다. 프로젝트 문서에서 시각을 어느 시간대로 저장하는지 확인하고 비교한다.

## 로그

조회 스크립트는 `<이 스킬 폴더>/scripts/log-query.mjs`이고, 플러그인의 `scripts/log-query.mjs`를 가리키는 심링크다. db 조회처럼 allowed-tools가 이 명령을 허용하므로 조회마다 사용자에게 묻지 않고, 경로를 글자 그대로 쓰는 규칙과 프로젝트 권한 설정도 db 절을 따른다. 메인 체크아웃에서 돌린다.

- 지금 컨테이너 로그는 `--since`로 시작 시각을 주고 `--grep`이나 `--regex`로 기준에 적힌 낱말을 찾는다. `--grep`을 여러 번 주면 모두 들어간 줄만 나온다. 시각은 `'9/24 23:31'`, `'2026-09-24 23:31'`, `6h`처럼 쓰고, 이 컴퓨터의 시간대로 읽는다.
- 배포 때 저장한 로그 파일은 `--list`로 이름을 보고 `--file <이름>`으로 읽는다. 컨테이너 로그 출력에 첫 줄이 `--since`보다 늦다는 알림이 붙으면 그 사이 배포 때 저장한 파일을 이어서 읽는다.
- 원격에는 정해진 읽기 명령만 가고, 거르는 일은 이 컴퓨터에서 한다. 출력은 기본 50줄, 한 줄 300자에서 잘리고, 스크립트가 토큰·키 모양 문자열과 주소를 가린다. 몇 번 나왔는지만 필요하면 `--count`를 쓴다.
- 접속 정보는 메인 체크아웃 `.env`의 `LOG_QUERY_SSH_HOST`, `LOG_QUERY_CONTAINER`이고, 없으면 `DB_QUERY_SSH_HOST`, `DB_QUERY_CONTAINER`를 쓴다. 저장한 로그 파일은 `LOG_QUERY_DIR`에 적은 서버 폴더에서 찾는다. 고정 규칙은 db 절과 같아서, 사용자가 `LOG_QUERY_DIR`를 새로 넣으면 다시 고정해야 로그 조회가 돈다. 설정 오류로 끝나면 env-has로 이름이 있는지만 보고 빠진 이름을 사용자에게 알린다. 값은 사용자가 넣는다.
- 종료 코드는 db 조회와 같다. 입력이 커서 끝까지 못 봤다는 알림과 함께 1로 끝나면 시각 범위를 좁혀 다시 본다.
- 컨테이너를 다시 만들면 로그가 사라지므로, 다음 배포 전에 로그로만 볼 수 있는 항목은 기한이 남아 있어도 이번에 본다.

## 슬랙

Slack MCP의 읽기 도구인 `slack_search_public_and_private`, `slack_read_channel`, `slack_read_thread`로 프로젝트 LOCAL 파일에 적힌 채널을 본다. 배포 시각 뒤의 게시만 보고, 판정에 쓴 글은 게시 날짜와 시각을 확인 결과에 적는다. 메시지를 보내거나 리액션을 다는 도구는 쓰지 않는다.

## 대화

대화 항목은 사용자에게 묻는다. 볼 장면을 사용자가 찾기 쉽도록, DB나 슬랙에서 해당 턴의 시각을 찾을 수 있으면 질문에 함께 적는다.
