# 지휘 세션

한 대화가 자율 진행 줄을 따라 세션마다 worker를 띄워 PR까지 맡기고, 검증을 거쳐 직접 머지하는 지휘 방식의 절차다. `SKILL.md` 「자율 진행」 절과 함께 따른다.

지휘 세션의 맥락은 도구를 부를 때마다 처음부터 다시 읽혀서, 지휘가 읽은 파일과 받은 보고가 쌓일수록 밤새 모든 호출이 비싸지고 압축도 잦아진다. 그래서 지휘는 순서와 판단만 맡고, 읽기와 구현과 리뷰는 에이전트에게 맡겨 결론만 받는다. 정확도에 드는 단계는 줄이지 않고, 같은 내용을 두 번 읽거나 두 번 검증하는 일만 없앤다.

## 시작

- 자율 진행은 새 대화에서 시작한다. 낮에 설계나 구현을 하던 대화에서 이어 시작하면 그 맥락이 밤새 호출마다 다시 읽힌다.
- 대기열은 `queue-read.mjs --auto`로 지금 계획만 읽고, 열 세션은 `--row <세션>`으로 그 행만 읽는다. 스크립트 경로와 명령은 `<이 스킬 폴더>/../next/SKILL.md` 1단계에 있다.
- 지휘는 대기열 파일, 설계 문서, 이슈 본문, PR diff를 통째로 읽지 않는다. 판단에 한 절이 필요하면 `grep -n`으로 줄을 찾아 그 범위만 읽는다.

## worker

- 세션 하나에 worker 하나를 띄운다. 같은 파일을 고치는 세션은 동시에 띄우지 않는다.
- model에는 행의 모델 칸 값을 그대로 주고, 칸이 비었으면 opus를 준다. sonnet 행을 opus로 올리지 않는다.
- 지시서에는 아래 5가지를 넣는다.
  1. 따를 절차: `<이 스킬 폴더>/SKILL.md`의 1~4단계와 6단계 PR과 CI까지, 그리고 「자율 진행」의 묻는 대신 가정하기 규칙. 5단계 리뷰는 지휘가 따로 맡기므로 하지 않고, PR 본문의 코드 리뷰 결과 절은 리뷰를 받은 뒤 채운다고 적는다. 경로는 realpath로 푼 절대 경로로 적는다.
  2. 행 칸: `--row` 출력을 그대로 옮겨서 worker가 대기열 파일을 다시 읽지 않게 한다.
  3. 읽을 곳: 설계 문서는 파일과 절 이름으로 적는다.
  4. 프로젝트가 정한 금지 사항: 평가 케이스를 새로 만들지 않는다는 줄처럼 대기열 진행 방식에 적힌 것.
  5. 보고 형식: 15줄 안에서 PR 번호, CI 결과, 바꾼 파일, 「아침에 확인할 것」에 적을 것, 검증받을 주장 3개까지.
- 리뷰나 검증에서 고칠 것이 나오면 새 worker를 띄우지 않고 SendMessage로 같은 worker에게 맡긴다. 같은 worker는 이미 읽은 맥락이 있어서 문서를 다시 읽지 않는다.

## 기다리기

- worker와 리뷰 에이전트는 백그라운드로 띄우고 끝났다는 알림을 기다린다. sleep 뒤 상태를 다시 보는 반복은 하지 않는다.
- CI는 `gh pr checks <N> --watch`를 Bash의 `run_in_background`로 돌려 끝난 알림을 받고 결과만 본다. 머지 뒤 base 브랜치 CI도 `gh run watch <run-id>`를 같은 방식으로 돌린다.
- 기다리는 동안 파일이 겹치지 않는 다음 세션의 worker를 띄운다.

## 리뷰와 검증

- PR마다 리뷰 에이전트 하나를 띄운다. subagent_type은 verifier, model은 opus로 주고, `<이 스킬 폴더>/../review-code/SKILL.md` 절차로 PR diff를 리뷰하면서 worker가 보고한 주장을 반박해 보라고 맡긴다. 지시서에는 PR 번호, 행의 할 일, worker의 주장만 넣고 diff는 에이전트가 읽는다.
- 같은 PR에서 나온 주장은 이 에이전트 하나에 묶는다. 보안, DB 스키마, 운영 데이터, 되돌릴 수 없는 변경에 대한 주장만 verifier를 따로 띄운다.
- 보고는 고칠 것과 주장마다의 판정을 근거 한 줄씩 붙여 10줄 안에서 받는다. 리뷰가 끝나면 그 보고를 SendMessage로 같은 worker에게 보내, REFUTED나 UNCERTAIN과 고칠 것은 같은 브랜치에서 고치고 PR 본문의 코드 리뷰 결과 절에 고친 것과 안 고친 까닭을 채우게 한다. 고친 뒤 다시 볼 때는 고친 부분만 같은 리뷰 에이전트에게 SendMessage로 맡긴다.

## 머지와 기록

- 머지는 「자율 진행」의 머지 순서대로 지휘가 한다. 문서 색인처럼 여러 PR이 함께 고치는 파일의 충돌은 지휘가 머지할 때 맞춘다.
- 머지한 뒤 8단계 마무리는 SendMessage로 같은 worker에게 맡긴다.
- 대기열에는 다음 판단에 필요한 줄만 적는다. PR 번호, CI 결과, 「아침에 확인할 것」 항목이 여기에 들고, worker 보고를 대기열이나 채팅에 다시 옮겨 적지 않는다.
- 완료 보고는 줄이 끝나거나 멈출 때 한 번 한다.
