# 인터뷰 사고 추출 기준

> 설계 인터뷰 중 발생한 사고 흐름 중에서 **휘발되면 안 되는 것**을 자동 식별한다.

## 추출 대상

다음 유형을 발견하면 추출 후보:

### 1. 의사결정 분기점
- "A안 / B안 / C안 중 X를 택했다 — 이유: ..."
- 단순히 결과만이 아니라 **왜 그 선택이 다른 선택을 이겼는지**까지

### 2. 포기한 안
- "Y는 고려했지만 안 했다 — 이유: ..."
- 같은 함정에 다시 빠지지 않기 위한 기록

### 3. 미룬 항목
- "이건 Phase N으로 보냈다 — 이유: 지금은 ..."
- "이 부분은 일단 1차 운영 후 결정"
- 미래 결정 일정과 트리거 조건 함께 기록

### 4. 회고 / 자신 없는 부분
- "이 부분은 가설로 두고 가는데..."
- "이게 맞는지 확신은 없지만..."
- 검증 시점에 다시 돌아볼 수 있도록

### 5. 비자명한 제약
- "X 때문에 이 방식을 못 쓴다"
- 코드만 봐서는 안 보이는 외부 제약

## 추출 대상 **아님**

- 코드 자체에서 자명한 정보 (함수 이름, 디렉터리 구조 등)
- 인터뷰 진행 메타 (질문 수, 시간, 인터뷰 순서)
- 단순 사실 확인 (이미 ADR/계획서/코드에 적힌 내용)
- 일반론적 베스트 프랙티스 (이 프로젝트 특수성 없음)

## 개수

**고정 개수 없음**. 0개부터 여러 개까지 자유. 기준에 부합하는 항목만 자연스럽게 추출.

- 0개일 수도 있음 (간단한 기능, 분기점 없는 결정)
- 5개 이상일 수도 있음 (마스터급 설계, 여러 phase 결정)

억지로 채우거나 잘라내지 말 것.
