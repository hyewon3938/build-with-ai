# 규모 판단 기준

## 소규모

다음 조건을 **모두 만족**하면 소규모:

- 변경 파일 1\~2개
- 로직 변경 최소 (오타, 임계치 조정, 단일 함수 수정 등)
- 새 기능 추가 X
- 구조 변경 X (디렉터리 추가, 인터페이스 변경 등)
- 외부 시스템(외부 API, DB 스키마, 인프라) 영향 없음

### 처리 방식

이슈/브랜치/PR 없이 직접 처리:
1. 코드 수정
2. 커밋 (프로젝트 Conventional Commits 컨벤션 따름)
3. 사용자에게 "소규모로 판단, 직접 처리" 안내

## 중규모 이상

다음 중 **하나라도 해당**되면 중규모 이상:

- 변경 파일 3개+
- 새 기능 추가 (사용자가 인식할 변화)
- 구조 변경 (디렉터리 신설, 타입/스키마 변경, 마이그레이션 등)
- 외부 시스템 영향 (DB 스키마, API 변경, 배포 설정 등)
- 보안 관련 변경 (인증/인가, 입력 검증, secrets 처리 등)

### 처리 방식

`/design` 전체 흐름 진행 (이슈 → 브랜치 → 계획서 → 사용자 확인 → /build).

## 판단 애매하면

작은 쪽으로 가정하고 시작하되, 탐색 중 영향 범위가 커지면 즉시 중규모로 전환하고 사용자에게 알린다.
