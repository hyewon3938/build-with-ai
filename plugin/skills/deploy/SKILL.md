# /deploy - 배포 스킬

머지된 변경을 운영에 올린다. 서버 주소와 명령은 프로젝트 LOCAL 파일의 배포 절에 적힌 대로 쓰고, 운영 서버에 명령을 보내기 직전에 사용자 확인을 한 번 받는다. 올린 뒤에는 배포 기록을 남기고 배포 뒤 확인 목록에 배포 시각을 넣는다.

## 입력

$ARGUMENTS

- 비어 있으면 base 브랜치 최신 커밋을 올린다.
- 커밋을 받으면 그 커밋까지만 올린다.
- 함께 할 일을 받으면 사전 확인과 배포 단계에 넣는다. 외부 지시서 패치 적용이나 운영 DB 조회가 그 예다.

## 경로 규칙

메인 체크아웃은 `git worktree list --porcelain`의 첫 `worktree` 줄이다. git 명령과 배포 명령은 메인 체크아웃에서 돌리고, LOCAL 파일도 메인 체크아웃의 절대 경로로 읽고 고친다.

## 실행 흐름

### 1. 배포 절과 앞 배포 확인

프로젝트 LOCAL 파일에서 배포 절을 찾아 그 절만 읽는다. 서버 접속, 백업, 올리기, 빌드와 재시작, 상태 확인 명령이 적힌 절이다. 배포 절이 없으면 멈추고, 이 명령들을 LOCAL 파일에 적어 달라고 알린다.

`LOCAL-HISTORY.md`의 마지막 배포 기록에서 앞 배포 커밋을 얻는다. 기록이 없으면 앞 배포 커밋을 묻는다.

메인 체크아웃이 base 브랜치가 아니거나 추적 중인 파일에 커밋하지 않은 변경이 있으면 멈춘다. 그 밖에는 `git pull --ff-only`로 base 브랜치를 원격 최신으로 맞춘다.

### 2. 올릴 내용과 배포 단위

`git log --first-parent --oneline <앞 배포>..<올릴 커밋>`으로 앞 배포 뒤 머지된 PR을 나열한다. `LOCAL-SESSIONS.md`가 있으면 대기열 행의 상태와 배포 묶음 칸을 대조한다.

배포 단위는 아래 3가지 기준으로 정하고, 기준에 어긋나는 점은 4단계 질문에 함께 적는다.

- 운영에서만 보이는 확인 항목이 2~3개 모이면 올린다.
- 스키마나 외부 발송 경로를 바꾸는 세션은 그 세션만 올린다.
- 같은 배포 묶음의 세션 하나가 밀리면 머지된 나머지를 먼저 올린다.

### 3. 사전 확인

- 검사: 프로젝트의 타입 검사와 테스트를 로컬에서 돌리고, CI가 있으면 올릴 커밋의 CI 결과도 본다. 실패하면 멈춘다.
- 옛 사본: `git diff --diff-filter=DR --name-only <앞 배포>..<올릴 커밋>`으로 지우거나 이름을 바꾼 파일을 찾는다. `--delete` 없는 올리기는 이 파일들을 원격에 그대로 두므로 5단계에서 지운다.
- 올릴 파일: 배포 절의 올리기 명령에 dry run이 있으면 돌려서, 올라갈 파일 목록을 `git diff --name-only <앞 배포>..<올릴 커밋>`과 대조한다. 목록에 없는 파일이 나오면 제외 목록이 바뀌었는지, 운영에서 손으로 고친 파일인지 확인하고, 이유를 모르면 4단계 질문에 적는다.
- 함께 할 일: 입력으로 받은 일과, 머지된 PR 본문이나 LOCAL 파일에 배포 때 할 일로 적힌 것을 모은다.

### 4. 사용자 확인

AskUserQuestion으로 묻는다. 질문에는 앞 배포 커밋과 올릴 커밋, 함께 올리는 PR, 지울 옛 사본, 함께 할 일, 2단계 기준에 어긋난 점을 적는다. 선택지는 아래 3개다.

- 배포: 5단계를 진행한다.
- 일부만 올리기: 올릴 커밋을 다시 받아 2단계부터 한다.
- 멈추기

### 5. 배포

배포 절의 명령을 아래 순서로 돌린다. 한 단계라도 실패하면 거기서 멈추고 실패한 명령과 출력을 보고한다. 되돌리기는 사용자가 정한 뒤에 한다.

1. 백업: 배포 절에 백업이 있으면 하고, 무결성 검사 결과와 파일 크기를 적어 둔다.
2. 로그 저장: 컨테이너를 다시 만드는 배포면 기존 로그가 함께 사라지므로, 배포 절에 이 단계가 없어도 로그를 서버의 파일로 저장한다.
3. 올리기: 올린 뒤 dry run을 다시 돌려 남은 차이가 0개인지 본다.
4. 옛 사본 지우기: 3단계에서 찾은 파일을 원격에서 지운다. 빌드가 소스 폴더를 이미지로 복사하는 프로젝트가 있어서 빌드 전에 지운다. 지우기 전에 지울 원격 경로를 알린다.
5. 빌드와 재시작
6. 상태 확인: 컨테이너 상태와 기동 로그의 오류를 보고, 바꾼 파일 2~3개의 해시를 올린 쪽과 실행 중인 쪽에서 대조한다. 배포 절에 확인 명령이 더 있으면 함께 돌린다.

함께 할 일은 상태 확인 뒤에 한다. 운영 데이터를 고치는 일이면 명령과 영향 범위를 알리고 한 번 더 승인을 받는다.

### 6. 기록

`references/records.md`에 적힌 형식대로 세 파일을 고친다.

- `LOCAL-HISTORY.md`: 배포 기록을 붙인다.
- `LOCAL-TRACK.md`: 올린 PR의 묶음 머리 줄에 배포 시각을 넣는다. 묶음이 없는 PR은 운영에서 볼 것이 있을 때 묶음을 새로 만든다.
- `LOCAL-SESSIONS.md`: 파일이 있으면 올린 세션의 대기열 행을 지우고, 마지막 배포와 배포 자리를 적은 줄을 고친다.

## 완료 보고

첫 줄에 올린 커밋과 배포 시각을 쓴다. 그 뒤에 함께 올린 PR, 상태 확인 결과, 지운 옛 사본을 적는다. 마지막에 `LOCAL-TRACK.md`에서 기한이 지난 확인 항목 개수를 알리고, 1개 이상이면 `/track`을 부르라고 안내한다. 기한은 `<이 스킬 폴더>/../track/references/checks.md`의 기한 계산대로 구한다.

## 주의사항

- 서버 주소, 경로, 명령, 배포 기록은 LOCAL 파일에만 적는다. 이슈, PR, 커밋 메시지 같은 공개 텍스트에는 옮기지 않는다.
- 비밀 값이 든 파일을 읽거나 출력하는 명령은 쓰지 않는다. 환경 변수가 있는지만 볼 때는 `<이 스킬 폴더>/../../scripts/env-has.mjs`를 쓴다.
