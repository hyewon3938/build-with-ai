# /review-code - 코드 리뷰 스킬

현재 브랜치의 변경사항에 대해 보안 감사 + 코드 품질 리뷰 + 컨벤션 점검 + 리팩토링 제안을 수행한다.

## 입력

$ARGUMENTS

인자가 없으면 현재 브랜치의 base 브랜치(main/master 등) 대비 전체 변경사항을 리뷰한다.
파일 경로가 주어지면 해당 파일만 리뷰한다.

## 실행 흐름

### 1. 변경 범위 파악

```bash
# base 브랜치 자동 감지 (main, master 등)
git diff <base-branch>...HEAD --stat
git diff <base-branch>...HEAD
```

변경된 파일 목록과 diff를 확인한다.

### 2. 보안 감사 (최우선)

가장 먼저 보안 이슈를 점검한다:

| 점검 항목 | 심각도 |
|----------|--------|
| 크리덴셜 하드코딩 (API 키, 비밀번호, 토큰) | CRITICAL |
| 환경변수 파일이 커밋에 포함됨 | CRITICAL |
| SQL Injection 가능성 (raw query 사용) | HIGH |
| 외부 입력 미검증 | HIGH |
| 민감 정보 로그 출력 | MEDIUM |
| 에러 메시지에 내부 정보 노출 | LOW |

CRITICAL/HIGH 이슈 발견 시 즉시 사용자에게 알린다.

### 3. 코드 품질 리뷰

프로젝트 컨벤션(`docs/conventions.md` 등)에 정의된 코드 품질 기준을 참조하여 점검한다.
컨벤션 파일이 없으면 일반적인 코드 품질 기준(타입 안전성, 단일 책임, 레이어 분리, 네이밍, 가독성 등)으로 점검한다.

### 4. 리팩토링 제안

프로젝트 컨벤션에 정의된 리팩토링 기준을 참조한다.
컨벤션 파일이 없으면 일반적인 리팩토링 기준(코드 중복, 함수 길이, 파일 크기, 추상화 수준 등)을 적용한다.

각 제안에 "지금 고칠 것" vs "나중에 고칠 것" 판단을 포함한다.

### 5. 리뷰 결과 출력

```markdown
## 코드 리뷰 결과

### 보안 감사
- [PASS/FAIL] 크리덴셜 하드코딩: [결과]
- [PASS/FAIL] 입력 검증: [결과]
- ...

### 코드 품질
- [PASS/WARN] 타입 안전성: [설명]
- [PASS/WARN] 구조/설계: [설명]
- ...

### 리팩토링 제안
1. [지금] [파일:라인] [제안 내용]
2. [나중에] [파일:라인] [제안 내용]

### 요약
- 보안 이슈: N개 (CRITICAL: N, HIGH: N)
- 품질 경고: N개
- 리팩토링 제안: N개 (즉시: N, 나중: N)
```

### 6. 수정 제안

CRITICAL/HIGH 보안 이슈가 있으면 수정 코드를 제안한다.
사용자가 수정을 원하면 바로 적용하고 커밋한다.

## 주의사항

- 보안 이슈는 반드시 먼저 확인하고 CRITICAL은 즉시 보고
- 리뷰는 프로젝트 컨벤션 기준으로만 판단 (개인 취향 배제)
- 리팩토링 제안은 현재 규모에 맞는지 판단 포함
- 칭찬할 부분도 언급 (좋은 패턴, 깔끔한 구현)
