# 멀티에이전트 오케스트레이션 이식 — 모델의 습관을 설정으로 옮기기

> 2026-07. 상위 티어 모델로 작업하면서 체감한 "일 잘하는 패턴"을 관찰해서, 어떤 모델로 세션을 열어도 같은 방식으로 동작하도록 표준 설정으로 이식한 기록.

## 문제

같은 Claude Code라도 모델에 따라 작업 스타일이 다르다. 상위 모델은 큰 요청을 받으면 알아서 쪼개서 서브에이전트를 병렬로 굴리고, 결과를 반박 검증한 뒤 종합해서 보고한다. 하위 모델은 같은 도구를 갖고 있어도 혼자 순차적으로 다 읽고 다 하려는 경향이 있다 — 컨텍스트가 금방 오염되고, 세션이 길어지면 판단이 흐려진다.

관찰해 보니 격차의 상당 부분은 지능이 아니라 **습관**이었다. 습관이라면 지시로 이식할 수 있다.

## 관찰한 패턴 5가지

1. **컨텍스트 예산 관리** — 메인 컨텍스트를 지휘실로 취급한다. 대량 파일 읽기는 서브에이전트에 시키고 결론만 받는다. 파일 덤프가 메인 컨텍스트에 쌓이지 않으니 긴 세션에서도 판단이 유지된다.
2. **병렬 기본값** — 독립 작업이 2개 이상이면 한 메시지에 Task 호출을 묶어 동시 실행한다. 순차는 의존성이 있을 때만.
3. **지시서 품질** — 서브에이전트 프롬프트에 목적+배경 / 범위 / 반환 형식 / 금지 사항 4요소를 반드시 채운다. 위임 실패의 대부분은 모델 탓이 아니라 지시서 탓이다.
4. **적대적 검증** — 중요한 발견은 별도 에이전트에게 "반박해 보라"고 시켜서 살아남은 것만 보고한다.
5. **턴 종료 규율** — 턴 마지막 문단이 계획이나 약속("이제 \~하겠다")이면 끝내지 않고 그 일을 실제로 한다. "알아서 끝까지 완수한다"는 체감은 대부분 이 규칙 하나에서 나온다.

## 설계 — 3층 progressive disclosure

전부 전역 프롬프트에 넣으면 매 세션 토큰을 잡아먹는다. 로드 시점 기준으로 3층으로 나눴다:

| 층 | 위치 | 로드 시점 | 담는 것 |
|----|------|----------|--------|
| 정책 | `~/.claude/CLAUDE.md`가 import하는 `orchestration.md` | 모든 세션 | 위임 기준, 병렬 원칙, 턴 종료 규율 (얇게) |
| 에이전트 | `~/.claude/agents/{scout,worker,verifier}.md` | 스폰될 때만 | 각 역할의 시스템 프롬프트 + 반환 형식 |
| 스킬 | `~/.claude/skills/orchestrate/SKILL.md` | `/orchestrate` 호출 시 | 전체 플레이북 (규모 가이드, loop-until-dry 등) |

`/design`·`/build` 스킬을 쪼갤 때 쓴 progressive disclosure와 같은 원리다 — 항상 필요한 건 얇게 상주시키고, 가끔 필요한 건 필요할 때만 로드한다.

역할 3종에는 모델 티어링을 적용했다. scout(탐색)는 빠른 모델로 충분하고, worker(구현)·verifier(검증)는 메인 세션과 동급 모델을 상속받는다. 판단 품질이 필요한 곳에만 비싼 모델을 쓰는 구조.

## 배운 것

- **행동은 이식되고, 판단은 이식되지 않는다.** 워크플로우의 형태(분해→병렬→검증→종합)는 설정으로 재현되지만, 분해를 얼마나 잘 쪼개는지, 종합이 얼마나 날카로운지는 여전히 모델 몫이다. 그래도 형태만 이식돼도 체감 격차가 크게 줄어든다.
- **검증자의 정의가 결과를 가른다.** "이 결론을 검증해줘"라고 하면 대부분 통과시킨다. "이 결론을 무너뜨려 봐, 실패하면 그때 CONFIRMED"로 역할을 정의해야 실제 필터가 된다. 확인자가 아니라 반박자.
- **자율성 지시에는 정지 조건과 명확화 규율을 함께 넣어야 한다.** "끝까지 알아서 해"만 넣으면 두 방향으로 실패한다 — 파괴적 작업까지 알아서 하려 들거나, 핵심 의도를 넘겨짚고 엉뚱한 걸 끝까지 완성한다. 그래서 두 짝을 같이 명시했다: ① 정지 조건(파괴적·비가역 작업, 사용자 고유 결정, 진단만 요청받은 경우엔 멈춘다) ② 명확화 규율(의도·맥락이 갈리고 틀리면 되돌려야 하는 지점은 넘겨짚지 말고 핵심만 묶어 한 번에 물어본다). 자율 완수와 "함부로 추측 안 하기"는 대립이 아니라 같이 가야 하는 짝이다. 이 균형은 첫 세팅엔 빠져 있다가 사용자가 "애매하면 인터뷰로 물어봐"라고 교정해 준 뒤에야 들어갔다 — 자율성만 강조하면 과잉 위임으로 기운다는 실제 증거다.
